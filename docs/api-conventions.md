# Соглашения публичного API

## Protobuf и JSON

Protobuf является источником истины для gRPC, HTTP-маршрутов и OpenAPI.
Публичный JSON использует `snake_case`: Gateway включает `UseProtoNames`, а
генератор OpenAPI запускается с `json_names_for_fields=false`.

Цена возвращается как `price` в основных денежных единицах. Способ хранения
денег внутри сервиса не является частью публичного контракта. Если Catalog
хранит цену в minor units, преобразование выполняется до создания protobuf
ответа:

```text
price = price_minor_units / 100
```

В реальном каталоге коэффициент должен зависеть от валюты: не каждая валюта
имеет два знака после запятой. До появления денежной модели это отмечено как
ограничение учебной реализации.

## Совместимость

- Номер опубликованного protobuf-поля нельзя переиспользовать.
- Удалённые номера и имена нужно помечать `reserved`.
- Перед слиянием контракта выполняется `make proto-breaking`.
- Изменение типа существующего поля считается breaking change.

Текущее переименование цены допустимо только потому, что API ещё не выпущен.
После первого релиза подобное изменение потребует нового поля или новой версии
API.

Ограничения Protovalidate не полностью переносятся в OpenAPI автоматически.
Значимые для HTTP-клиента ограничения нужно дополнительно описывать в OpenAPI
аннотациях и проверять тестами спецификации.

## Ошибки

Gateway возвращает единый JSON:

```json
{"code":"InvalidArgument","message":"validation error"}
```

Коды gRPC остаются стабильными машинными идентификаторами. Внутренние детали
ошибок с кодами `Internal`, `Unknown` и `DataLoss` клиенту не раскрываются.
Один HTTP-запрос создаёт одну итоговую запись в access log; исходная ошибка
добавляется в эту запись.

Кастомные BFF handlers не попадают в сгенерированный OpenAPI автоматически.
При их появлении нужно добавить отдельное описание или overlay и контрактный
тест.
