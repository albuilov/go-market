# Эксплуатация

## Health endpoints

- `/healthz` проверяет, что процесс Gateway работает. Он не обращается к
  зависимостям.
- `/readyz` проверяет обязательные зависимости Gateway и исключает экземпляр
  из трафика при их недоступности.
- gRPC-сервисы публикуют стандартный `grpc.health.v1.Health` для каждого
  зарегистрированного service name.

Успешные health-запросы не пишутся в access log, чтобы не создавать шум.
Неуспешная readiness-проверка логируется и возвращает HTTP 503.

## Завершение работы

`main` отменяет корневой context по `SIGINT` или `SIGTERM`. После этого сервер
перестаёт считаться готовым, прекращает принимать новые запросы и ожидает
текущие запросы не дольше настроенного shutdown timeout. После timeout
соединения закрываются принудительно.

Timeout приложения должен быть меньше grace period оркестратора, иначе процесс
может быть остановлен до завершения собственного shutdown.

## Диагностика

Логи пишутся в JSON и всегда содержат имя сервиса. Request ID проходит из HTTP
в gRPC и возвращается клиенту. Ошибки клиента логируются один раз в итоговой
HTTP-записи на уровне `WARN`, серверные ошибки — на уровне `ERROR`.

Метрики и tracing пока не входят в базовый шаблон. Точки расширения для них —
HTTP middleware и gRPC interceptors; добавлять отдельный abstraction layer до
выбора конкретного backend не нужно.
